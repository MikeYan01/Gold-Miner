# 当前游戏的单关收入上界与后期目标曲线

核查日期：2026-09-22。

**后续实施状态（2026-09-25）：本报告的25,400／36,000严格保证候选没有采用。** 游戏先按 [后续多配装实测](post-ten-income-samples.md)采用10,000封顶，现已下调为8,000：第11～20关线性提高增量，第21关起固定8,000，见 [`runLevelTarget`](../../src/game/economy.ts)。下文保留原始上界推导，不应将它当成现行目标配置。

**后续能力调整（更新至2026-09-26）：** 金块收藏家提高至30%，钻石收藏家仍为15%；大力提高至50%并恢复普通钱袋奖池。“富贵险中求”的判定基础半径为TNT爆炸半径的75%；璀璨胜金改为抓取时20%转换。时间银行、争分夺秒、点石成金、骨头供给、黄金生长和压哨交货也已加强，现行规则见 [README](../../README.md#run-abilities)。以下旧名称、数值和推导保留为2026-09-22快照，未按新参数重新计算，不能继续视为当前版本的保证上界。

**后续爆炸调整：** 当前TNT半径为250、优先局部连锁，不再额外按视口长边放大。本文的限时采样使用此前300半径及全图连锁偏好；金额放宽上界忽略了这些采集约束，仍不能等同于当前实玩收入。

## 结论与范围

**不要把“最富的一关”“固定配装的七关平均收入”“限时内实际挖到的钱”当成同一个数。**

本报告以当前本地 TypeScript 源码及真实 `GameEngine` 为准，不沿用历史原版资源表的面值，也不引用外部网页。只研究收入与候选目标，**没有修改目标、生成、能力、结算或测试代码**。商店去通胀由另一个修改处理；这里不分析报价，统一把购买支出放宽为零。因此计算的是**毛收入上界**，购买只能让钱包净增长更低，不会使以下保证失效。

| 指标 | 单人 | 双人全队 |
| --- | ---: | ---: |
| 第11关以后，任意合法四能力的单关毛收入保守上界 | 32,455 | **34,281** |
| 第25关起，同一四能力连续七关的毛收入保守上界 | 156,484 | **168,769** |
| 上一行除以7 | 22,354.86 | **24,109.86** |
| 仅服务各自模式时，单关上界加5%、向上取整到百元的封顶增量 | 34,100 | 36,000 |
| 仅服务各自模式时，七关均值上界加5%、向上取整到百元的封顶增量 | 23,500 | 25,400 |

这些是**已证明不会被超过的放宽上界，不是已证明能在时限内达到的最大值**。它们允许极端好运、最佳补给、全部宝藏获得危险加成，并忽略收集路径与部分时间冲突。真正可达最大值可能更低。

两种模式目前使用相同累计目标。如果要求“无论怎样好运，有限存款终会被追上”，推荐在本报告两种候选中选择：**第10关以后线性升至第20关增量25,400，之后固定25,400**。不必为了最富的单关把共同封顶增量提高到36,000；完整七关循环已经足以证明最终失败。但25,400仍是为极端随机结果留出的保守数，**不是普通玩家体验意义上的温和推荐值**，详见第7、8节。

## 1. 口径、资源类别与生成顺序

### 三种金额

- **`F₀`：无能力、无商店道具、不含袋内奖励的生成面值。** TNT按初始化的1元计入；这不是安全采集保证，也不是实际收入的下界。
- **`U`：所有合法四能力中的毛收入上界。** 允许最佳商店道具、最有利模板、钻石奇数向上保留、最多四袋全部最高现金，以及有利的能力判定；具体放宽见第4节。
- **实测收入：** 在真实时钟、碰撞、回拉和爆炸逻辑下，有限种子、固定操作策略实际入账的金额。样本最高值绝不代替`U`。

钱包是累计值，过关判断读取当前钱包；本关 `result.earned` 是钱包减去开局快照，包括时间银行，但不包括开局前已花的钱。源码：[`src/game/engine.ts:597–626`](../../src/game/engine.ts#L597-L626)、[`src/game/engine.ts:718–745`](../../src/game/engine.ts#L718-L745)。购买只扣钱包，见 `src/game/engine.ts:676`；本报告不继续研究商店定价路径。

### 类别与两个分界

第11关以后类别为：

```text
k(n) = 4 + ((n − 11) mod 7)
11…17 → 4,5,6,7,8,9,10
18…24 → 4,5,6,7,8,9,10
25…31 → 4,5,6,7,8,9,10
```

每类三个模板等概率抽取，重复的模板仍各占1/3。研究脚本直接调用 `getLevelInfo`、`originalResourceProfile` 核对这些映射，未把显示关数当成不断增长的资源类别。入口与模板选择：[`src/game/levels.ts:65–72`](../../src/game/levels.ts#L65-L72)、[`src/game/resource-profiles.ts:25–90`](../../src/game/resource-profiles.ts#L25-L90)、[`src/game/random.ts:9–14`](../../src/game/random.ts#L9-L14)。

当前生成顺序非常重要：

1. 中金、大金、散落钻石、携钻鼹鼠，分别将模板数量乘0.8再 `Math.round`；其余普通材料乘0.65再四舍五入。袋与TNT不走这一减密度步骤。
2. 双人第11、12关加 **1颗散落钻石＋1块大金**；第13关以后改为 **2颗散落钻石，不再加大金**。
3. 把此时的**全部散落钻石，包括双人增量**减半。偶数直接除2；奇数取下整，再独立以50%概率多留1颗。因此第13关起双人稳定比同模板单人多1颗散落钻石，而不是多2颗。
4. TNT数量取模板数与保底的较大者：1～3关保底3，4～24关保底4，25关起保底5。模板中的7个TNT仍是7个。
5. 袋数另抽0～4，不采用模板的袋数字段。“谁动了我的钻石”再加 **1只**携钻鼹鼠，双人也是全队1只；它不再减密度、不减半。
6. “璀璨胜金”对剩余**每块黄金各作一次10%判定**，转换后的钻石不再减半；原有携钻鼹鼠也没有“钻石减半”处理。

源码：[`src/game/levels.ts:22–25`](../../src/game/levels.ts#L22-L25)、[`src/game/levels.ts:115–164`](../../src/game/levels.ts#L115-L164)，概率常量见 [`src/game/abilities.ts:18`](../../src/game/abilities.ts#L18)。

## 3. 结算规则：不能把22个能力全叠在一起

能力ID共22个；最多持有4个，选卡节点是第1、4、7、10关，之后配装固定。每次展示3张，一局已展示的牌不会再次出现，四轮最多看到12张。拆弹专家与慢燃引信互斥。

来源：[`src/game/types.ts:5–28`](../../src/game/types.ts#L5-L28)、[`src/game/abilities.ts:12–13`](../../src/game/abilities.ts#L12-L13)、[`src/game/abilities.ts:64–85`](../../src/game/abilities.ts#L64-L85)、[`src/game/engine.ts:230–260`](../../src/game/engine.ts#L230-L260)。

### 普通物品的准确公式

令 `R` 为锁定的危险倍率1或1.5，`Q` 为争分夺秒倍率1或1.3，`G`、`D`分别为金块／钻石收藏家倍率1或1.1：

```text
黄金：    Math.round((黄金当前基础价 × G) × (R × Q))
钻石：    Math.round((600 + 抛光剂的300) × D × (R × Q))
携钻鼹鼠：Math.round(2 + (600 + 抛光剂的300) × D × (R × Q))
克隆物品：上述已取整单件收益 × 2
最后再加：本次恰好完成化石拼图时的500
```

没有抛光剂时，其300项取0。源码实际以 `Math.round` 对每件物品单独结算，**不能先汇总小数，也不能先克隆后取整**。例如抛光＋钻石收藏家＋险中求财＋争分夺秒的钻石取整为1,931，携钻鼹鼠为1,933；相应物品若在另一套合法四能力中获得克隆，分别为3,862、3,866。这里的克隆核对配装是“钻石收藏家＋险中求财＋争分夺秒＋克隆”，**没有第五张璀璨胜金**。

## 4. 上界怎样计算、哪里故意高估

### 有界穷举而非抽种子找“最大值”

1. 从真实能力列表枚举所有至多4张的兼容集合：**8,898个**；其中恰好4张有 **7,125个**。不是对每种物品分别挑最强四张。
2. 投影到13种会影响放宽毛收入的能力，得到 **1,093个**有效集合：金块收藏家、钻石收藏家、点石成金、璀璨胜金、拆弹专家、额外携钻鼹鼠、险中求财、时间银行、争分夺秒、考古学家、克隆、化石拼图、黄金生长。
3. 对每个固定集合、阶段、模式，穷举三个模板，散钻选择其数量上端，每袋最多800、袋数最多4，使用最佳价值道具。每件物品按JS原生运算顺序取整。
4. 有璀璨胜金时，所有黄金转成抛光钻石支配不转换：钻石基础900，黄金即使长满再加金块收藏家也最多550，危险与争分夺秒是共同倍率。因此求此上界不必再穷举每块金的转换子集，但这**绝不表示转换必定发生**。
5. 点石成金允许每块石头都成功。没有璀璨胜金时，用动态规划分配生长脉冲：每颗黄金有0～3档升级选项，总升级次数不能超过脉冲预算；同时选择最多一个克隆物品，不能让所有黄金免费满级。
6. 生长预算按普通单人6次、双人4次，争分夺秒单人4次、双人3次放宽。额外加至多一次化石奖金及时间银行上限。
7. 单关表取 `max_A max_模板 U(A,关)`；长期表则取 **`max_A Σ七类别 max_模板 U(A,类别)`**。后者的`A`在整轮七关中不变。

另外9张能力并未漏掉：

- 大力、钱袋子会改善速度、概率或奖池，但袋数上限仍4、最高现金仍800，所以不增加这个乐观现金包络。
- 射线、深渊巨口、透气的鼹鼠、慢燃引信、压哨交货影响操作或能否交付；模型本来就允许全部交付。慢燃可能使碎片更少，按普通TNT每个最多1元包住它是高估，不是漏算收益。
- 窃贼、老主顾减少购买成本或改善供货；模型已允许最优补给且支出为零。

上述能力的效果逐项见 [`src/game/abilities.ts:31–54`](../../src/game/abilities.ts#L31-L54)。因此投影不影响“覆盖所有合法配装”的上界结论，但**不代表这些牌对真实游戏不重要**。

### 明确保留的松弛

- 假定所有黄金／钻石，包括点石成金产物，都能在TNT附近抓住；没有证明随机布局能同时满足。
- 假定最终收齐所有宝藏而不被TNT误伤，且普通TNT数量每个都按1元算；链爆、挡路和先后顺序往往使两者不能同时达到。
- 克隆允许最值钱的对象成为首抓，未解“必须先移走障碍”的路径问题。
- 给有时间银行的配装同时计入完整材料收入和全部剩余时间上限；给黄金生长完整脉冲预算。**全收集、等满生长脉冲、满额提前收工奖金不能通常兼得。** 归零帧的未认领黄金长大，也不等于能在该帧立刻交付。
- 全现金最高奖袋没有提供袋中生力。大力水可用，但不能暗中把“四个现金大奖袋”又当成已经得到袋中生力。
- 忽略购买支出、瞄准等待、绳长、回拉耗时、移动鼹鼠、争分夺秒缩短时间等可达性限制；计入争分夺秒对银行／生长预算的缩短，但没有计算全地图最优路线。

这些处理都是向上放宽，不会漏掉更高收入。下面三个胜出配装均不含时间银行、黄金生长或克隆，所以这三项的时间／顺序松弛并未直接抬高最终胜出数；主要差距是极端随机、全部危险加成与实际采集约束。

### 最富的单关为何超过三万元

类别10模板1减密度后有 **15块金＋3块大石头**。第25关以后单人有5个TNT；双人还多1颗已减半的散落钻石。

单人胜出的A配装：

```text
15块黄金全部转换 → 15 × round(900 × 1.5 × 1.3) = 26,325
3块石头全部转金 → 3 × round(500 × 1.5 × 1.3)  =  2,925
四个最高现金袋                                      3,200
按每个TNT都能回收1元放宽                               5
合计                                               32,455
```

双人胜出的C配装：

```text
15块转换钻石＋1颗额外散钻 → 16 × 1,931 = 30,896
3块大石头，只用石头书      → 3 × 60    =    180
四个最高现金袋                           3,200
TNT碎片放宽                                  5
合计                                    34,281
```

C没有点石成金；A没有钻石收藏家。两种算法不能合并成一套五能力。

这不是常见收入。在独立均匀抽签模型下，仅“双人10_1模板、15块金全转换、四袋且全为普通800元顶奖”这组必要开奖条件的概率就是：

```text
(1/3) × 0.1^15 × 0.03 × (1/6)^4 ≈ 7.72 × 10^-21
```

尚未乘入取得对应配装、补给和可用布局的条件，也没有证明实际全收集。**极罕见不等于严格上界可以忽略它**；反过来也不能因为数值相乘得到34,281，就宣称它已经实际可达。

### 四轮选卡的可获得性

以下每个括号是一次三选一，首项是选择项。每套序列各有12张互不重复的牌，且由真实 `drawAbilityOffers` 的确定性洗牌输入验证，不是假定可以反复重抽已见卡：

- **A：**（点石成金、大力、金块收藏家）→（璀璨胜金、钻石收藏家、射线）→（险中求财、深渊巨口、拆弹专家）→（争分夺秒、谁动了我的钻石、钱袋子）。
- **B：**（璀璨胜金、大力、金块收藏家）→（谁动了我的钻石、钻石收藏家、点石成金）→（险中求财、射线、深渊巨口）→（争分夺秒、拆弹专家、钱袋子）。
- **C：**（钻石收藏家、大力、金块收藏家）→（璀璨胜金、点石成金、射线）→（险中求财、深渊巨口、拆弹专家）→（争分夺秒、谁动了我的钻石、钱袋子）。

这是“存在合法选卡序列”，不是每局都保证给齐，也不额外声称该序列在任意前十关开奖下都能存活。

### 为什么平均上界足以耗尽任意有限盈余

设封顶后每关累计目标增加`C`，第24关成功结算后高于目标的盈余为有限的`S₂₄`。商店支出非负，第25关起每完整七关：

```text
钱包最多增加 168,769
目标必定增加 7C
盈余最多变化 168,769 − 7C
```

所以只要 `C > 168,769 / 7`，不管富矿关暂时追回多少钱，完整循环后盈余都严格下降。取本报告候选`C=25,400`，**每七关至少消耗9,031盈余**。

若还能连续通过，最多经过 `floor(S₂₄ / 9,031) + 1` 个完整循环就会产生矛盾，因此必在此之前或该循环内某关失败。单人使用这个共同目标只会更早受到上界约束。这是对所有模板／奖励结果的确定性保证，不依赖“坏运气迟早会来”，也不要求每一关收入都低于25,400。

## 8. 两条具体线性增量曲线

脚本通过公开 `levelTarget` 核对第10关累计目标15,275、第9到10关增量2,705；目标入口见 [`src/game/levels.ts:65–72`](../../src/game/levels.ts#L65-L72)。以下只是候选计算，未修改实现。

统一规则：

```text
G(10) = 15,275
Δ(10) = 2,705
11 ≤ n ≤ 20:
  Δ(n) = Math.round(2,705 + (C − 2,705) × (n − 10) / 10)
  G(n) = G(n−1) + Δ(n)
n > 20:
  Δ(n) = C
  G(n) = G(20) + C × (n−20)
```

明确选择 **5%安全余量，再向上取整到100元**，不是先猜封顶数：

- **方案一：单关严格保证。** `C = ceil(34,281×1.05/100)×100 = 36,000`。相对上界高1,719，约5.014%；封顶后每一关都至少消耗1,719盈余。
- **方案二：完整七关保证。** `C = ceil((168,769/7)×1.05/100)×100 = 25,400`。相对七关均值上界高约1,290.14，约5.351%；每七关至少消耗9,031盈余。某个富矿关仍可能比25,400赚得更多。

### 线性不等于绝对难度更缓

与此前讨论、尚未实现的 `round(2705 × 1.2^(n−10))` 方案相比，以严格理论上界为终点的两条线性曲线，在第11～20关反而要求更多收入：

| 关 | 此前20%增量复利提案 | 七关保证线性方案 | 单关保证线性方案 |
| ---: | ---: | ---: | ---: |
| 11 | 3,246 | 4,975 | 6,035 |
| 15 | 6,731 | 14,053 | 19,353 |
| 20 | 16,749 | 25,400 | 36,000 |

因此“线性上升、约第20关封顶”和“比此前提案温和”不能只凭曲线名称同时保证；关键仍是封顶数。以上均为候选计算，未应用到游戏目标。

**推荐的取舍：**

1. 如果产品要求是“有限存款无论多大，最终都必须耗尽”，选择方案二更合理：共同封顶比方案一低10,600，同时仍有严格证明，不需要压过每一座富矿。
2. 如果产品要求还包括“普通玩家平顺玩到20关左右”，本报告不足以把25,400称为合适平衡。它第11关的增量已比2,705多2,270，最后远高于当前有限实测量级，可能让很多局在20关之前结束。需要另行依据真实跑局数据，决定是否接受概率意义而非所有随机分支下的保证；不能擅自拿样本最大值替代证明。
3. **“第20关达到封顶”不等于“第20关必结束”。** 第10关已有存款、11～20关的实际收入和支出、固定配装、富贫矿顺序都会改变结局。两个方案保证的是封顶后的负长期盈余变化，不是统一死亡关数。
4. 去掉商店通胀不使商品免费；本报告忽略费用是为了给保证留出更严格的对手条件。实际花钱只会加速盈余消耗，不能把这里的毛收入直接宣传成净利润。
